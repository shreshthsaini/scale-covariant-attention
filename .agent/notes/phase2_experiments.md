# Phase 2 experiments E1 to E7 and E9: spool tasks, outputs, evaluation

Written 2026-10-16 by the experiments engineer. All task files are generated by
`slurm/phase2_tasks.py` (idempotent: it never overwrites a task that already exists in pending,
running, done, failed or hold_phase2; `--dry-run` lists counts). Every task passed `bash -n`.

Shared protocol: FLUX.1-dev (Krea only in E9), guidance 4.5, 28 steps, mu = max_shift, seed 0
unless stated, per-prompt seeds and file stems from `image_stem(id, seed)` (identical in
sca/runtime.py, crope/utils.py and run_area.py). SCA final everywhere = `scripts/sample.py
--method sca --pi-table /scratch/09032/saini_2/sca/calib/k1_1024.npz --gate-sigma 0.89 --label
sca_nb` from `/scratch/09032/saini_2/sca/code/2d11740`. Task env: HF_HOME, TORCH_HOME,
HF_HUB_OFFLINE=1, XDG_CACHE_HOME, TRITON_CACHE_DIR, OMP_NUM_THREADS=8, and `unset
CROPE_TRANSFORMER CROPE_ROPE` (so the crope harness never silently loads Krea).

## Shared pieces

- Prompt lists (new, on scratch `/scratch/09032/saini_2/sca/`):
  - `eval100.jsonl`: the first 100 Aesthetic-4K eval prompts after removing dev4 (E2 6144, E9).
  - `hi12.jsonl`: 12 prompts, every 16th of the 191 non-dev prompts (indices 0, 16, ..., 176): planet,
    people, silhouettes, portrait, landscapes, desert, aurora, lake, window scene (E2 8192).
  - `hrgen200.jsonl`: HRGen-1K rows 0 to 199 with their own stable ids `hrgen_0000` to `hrgen_0199`
    (E4). The HRGen file already uses ids of that form, so they were kept unchanged.
- `scripts/link_common.py` (new, stdlib only): builds an eval root of symlinks over prompt ids that
  every method has completed, dev4 excluded; replaces the inline bash of the b999 template.
- Evaluation template (all `*_eval_*` tasks): wait until no generation task of the experiment is in
  pending/ or running/, print a WARNING for any of them in failed/, link the common ids into
  `out/evalroot/<name>`, run `eval_extra.py` (sca-metrics env) into `eval/<name>_extra`, then
  constancy_rope `eval.py` (sca env) into `eval/<name>_base`. Eval tasks are named to sort right
  after their generation tasks. As in the old campaigns, an eval task occupies a worker GPU while it
  waits for the last running chunk of its experiment.
- Frozen constancy_rope code for DyPE and SEGA: `/scratch/09032/saini_2/sca/code/crope_c05ebdc`
  (a git clone of constancy_rope at its HEAD c05ebdc; the live constancy_rope tree has uncommitted
  edits by another agent, which this avoids). Eval still uses the live constancy_rope `eval.py`, as
  in all earlier campaigns.
- Metric sets: 191 and 100 prompt sets use extra `ir,aesthetic,hpsv2,hpsv21,clipiqa,arniqa,is` and
  base `clip,pickscore,musiq,fid,kid,patch_fid,patch_kid` with Aesthetic-4K references; 46 prompt
  sets use extra without `is` and base `clip,pickscore,musiq,patch_fid,patch_kid`. Checked on CPU
  that `eval.py` runs without `--references` for clip/pickscore (references are only needed for
  FID/KID/spectrum/tiling).

## E6 calibration budget (prefix e, 30 gen + 1 eval)

- Tables built on CPU (done): `calib/k1_1024_n{4,8,16}.npz` and `.json`, from part dirs
  `calib/k1_1024_n{k}_parts/` that symlink the first k parts of `calib/k1_1024_parts/` plus a copy of
  its `calib_config.json`. Command (run from code/2d11740):
  `python scripts/calibrate.py --prompts /work/.../scripts/calib_prompts.jsonl --count k --res 1024x1024 --scales 2,4 --guidance 4.5 --out /scratch/09032/saini_2/sca/calib/k1_1024_nk.npz --report-only --transfer-with /scratch/09032/saini_2/sca/calib/k1_1024.npz --device cpu`
  (`--prompts` must be the work path, it is part of the stored settings). In-sample per-head
  rel_err at s=4: n4 0.188, n8 0.193, n16 0.198, n32 0.200; split-half correlation n4 0.93, n8 0.96,
  n16 0.98, n32 0.99. The small tables fit their own prompts better (overfitting), so generation is
  the real test. The `.json` holds a `transfer` block against the 32-prompt table.
- Tasks `e000..e045_sca_cal{4,8,16}_4096x4096.sh` (abl50, chunk 5), labels `sca_cal4/8/16`, outputs
  `out/calib_budget/sca_calk/4096x4096`. Command:
  `sample.py --method sca --seed 0 --guidance 4.5 --out <out> --pi-table calib/k1_1024_nk.npz --gate-sigma 0.89 --label sca_calk --res 4096x4096 --prompts abl50.jsonl --start a --end b`
- Eval `e998_eval_e6_calib.sh`: sca_nb (main 4K) + 3 tables, 46 prompts, reference sca_nb,
  `eval/e6_calib_{extra,base}`.
- About 3.9 GPU-hours (150 images at about 75 s plus load).

## E2 higher resolution (prefix i, 62 gen + 2 eval)

- 6144x6144: `i000..i096_{sca_nb,area}_6144x6144.sh` (eval100, chunk 4), outputs
  `out/main/{sca_nb,area}/6144x6144`. Eval `i998_eval_e2_6144.sh`, 100 prompts, full metric set with
  the 4096 px Aesthetic-4K references, reference area, `eval/e2_6144_{extra,base}`.
- 8192x8192: `i000..i010_{sca_nb,area}_8192x8192.sh` (hi12, chunk 2), outputs
  `out/main/{sca_nb,area}/8192x8192`. Eval `i999_eval_e2_8192.sh`: extra without IS, base
  `clip,pickscore,musiq` with `--allow-missing` (MUSIQ at native 8192 px may run out of memory), no
  references, reference area, `eval/e2_8192_{extra,base}`. Mostly for qualitative figures.
- Checks (CPU): SCA pool factors 6144 -> [6, 6], 8192 -> [8, 8]; the pi table uses its nearest
  calibrated scale 4 at both (and 3072 ties to 4, 2048 uses 2). Both samplers enable VAE tiling
  (sample.py for h*w >= 2048*4096, run_area always). AReA schedules build: 6144 factors start
  [6, 6, 4], windows end at 64; 8192 factors [8, 8, 8]. FLUX img_ids are bf16, so base RoPE
  positions above 256 tokens per axis are rounded for every method (known, Section 10 of HANDOVER).
- Memory not measured on GPU; at 8192 there are 262144 image tokens, about 1.6 GB per hidden-state
  tensor, which should fit a 96 GB GH200 for SCA; AReA at 8192 is the larger risk.
- About 20.5 GPU-hours at 6144 (SCA about 165 s, AReA about 530 s per image, extrapolated) and 4.5 at
  8192 (SCA about 290 s, AReA about 960 s).

## E3 latency curve (prefix y, 5 tasks + 1 summary)

- `y000_latency_2048x2048.sh` ... `y004_latency_8192x8192.sh`: each runs `lat3.jsonl` sequentially
  for SCA final, AReA and full attention (`sample.py --method full`), outputs
  `out/latency_curve/<res>/{sca_nb,area,full}`, and prints nvidia-smi apps first to show the GPU is
  otherwise idle. Full attention is skipped at 8192x8192 (echoed in the log). A failed method does
  not stop the others.
- `y999_summary_latency.sh` writes `eval/latency_curve.csv` and prints the median seconds per
  (res, method). Use the median of 3 (the first SCA image includes FlexAttention compile).
- About 3.5 GPU-hours, dominated by full attention at 6144 and AReA at 8192.

## UltraImage (E1, held)

- New wrapper `scripts/run_ultraimage.py` (CLI, seeding, stems and sidecars as run_area.py;
  sidecar method `ultraimage`, `--label` override, `--dry-run` on CPU). It runs the official
  UltraImage FLUX branch (`/scratch/09032/saini_2/constancy_rope/third_party/UltraImage/flux`,
  commit 586ae88) with its own FLUX.1-dev defaults from infer_unified.py and base.yaml, not our
  28 steps / 4.5: two stages of 30 steps, guidance 3.5 then 7 (super_imax schedule), time_shift
  3 and 6, sdedit_threshold 11, RIFLEx (linear_factor res/2048, train_length 4608), ntk_factor 10,
  text_duplication False, attention_decay operator with a 2+2 step block-average pre-pass per
  prompt. All settings are in the sidecar under `ultraimage`.
- Generator: CPU generator with the derived per-prompt seed plus `torch.manual_seed(derived_seed)`
  (the pipeline's VAE sampling uses the global RNG). Upstream uses a fixed seed 0 for every prompt.
- Upstream quirk kept: the code sets `scheduler.config.shift`, which never reaches the scheduler, so
  both stages actually run at shift 3. Both emulated sigma schedules are recorded.
- Compatibility: PyWavelets is missing from the sca env; the wrapper registers a numpy Haar
  replacement that matches PyWavelets 1.8.0 bitwise. sca/envfix is loaded by file path. Imports
  are clean under diffusers 0.39. Only square resolutions are supported (hard-coded 64x64 low-res
  grid).
- CPU checks: weight names match the checkpoint; a tiny end-to-end run at 2048 passed both stages,
  VAE and wavelet steps; dry-run of the held task command lists the right stems and cache dirs.
- Not validated on GPU. The jintao int8 Triton kernels are untested on Triton 3.6 / GH200 and are
  the likeliest failure. The first held task `g000_ultraimage_4096x4096.sh` doubles as the smoke
  test; if it fails, check `logs/task_g000_ultraimage_4096x4096.log` before letting the rest run.
- Tasks (held, PHASE2): `g000..g190_ultraimage_4096x4096.sh`, 195 prompts, chunk 5:
  `scripts/run_ultraimage.py --seed 0 --out /scratch/09032/saini_2/sca/out/main/ultraimage/4096x4096 --res 4096x4096 --prompts aesthetic4k_eval.jsonl --start a --end b`.
  Eval `g998_eval_e1_ultraimage.sh`: sca_nb, area, ultraimage, 191 prompts, reference sca_nb,
  `eval/e1_ultraimage_{extra,base}`.
- Expected 45 to 60 GB peak, roughly 250 to 350 s per image (stage 1 at 1024, stage 2 at 4096):
  about 17 GPU-hours. The block-average cache under
  `/scratch/09032/saini_2/sca/cache/ultraimage_blockavg/4096x4096/` takes about 1.5 GB per prompt
  (about 290 GB in total, on scratch).
